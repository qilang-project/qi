# qi 包管理设计（v1）

注册中心 pkg.qilang.org + 客户端 `qi 包` 子命令。本文件是两侧共同遵守的**协议合同**，
改协议先改这里。

## 设计取舍（v1 刻意收窄）

- **精确版本，不做 semver 范围解析**。范围解析（`^1.2`）是包管理器复杂度的大头，
  而 qi 生态现在包不到十个 —— 先让「发布/安装/锁定」跑通，范围解析等真有钻石依赖再说。
- **扁平安装**：全部依赖平铺进 `./qi_packages/<名称>/`，不做嵌套/去重图。编译器的
  包解析本来就认这个布局。同名不同版本冲突 = 报错让人挑，不静默选。
- **不做自助注册页**：v1 发布 token 由管理员生成。生态就这几个人。

## 包格式

- 一个包版本 = 一个 `tar.gz`：包根的 `qi.toml` + 全部源码文件。打包时排除
  `.git/ target/ tests/ *.o qi_packages/`。
- 包名 = qi.toml `[包] 名称`（可为中文，URL 中 percent-encode）。
- 版本：`主.次.补` 数字三段（如 `0.1.0`），只做相等比较。

## qi.toml 扩展

```toml
[依赖]
海龟 = "0.1.0"          # 从注册中心装精确版本
```

## 锁文件 qi.lock（TOML，提交进 git）

```toml
[[包]]
名称 = "海龟"
版本 = "0.1.0"
sha256 = "…"
来源 = "https://pkg.qilang.org"
```

安装时有 lock 按 lock 装并校验 sha256；无 lock 按 qi.toml 解析后写 lock。

## Registry HTTP API（全部 JSON UTF-8；线上协议键一律英文）

| 方法/路径 | 语义 |
|---|---|
| `GET /api/v1/packages` | 包列表 `{"packages":[{"name","latest","description","downloads"}]}` |
| `GET /api/v1/packages/{name}` | 详情 `{"name","description","versions":[{"version","sha256","size","uploaded_at"}]}` |
| `GET /api/v1/packages/{name}/{version}` | 单版本元数据（404 = 无此版本） |
| `GET /api/v1/packages/{name}/{version}/download` | tar.gz 包体裸字节（Content-Type: application/gzip，服务端 sendfile 直发） |
| `PUT /api/v1/packages/{name}/{version}` | 发布：body = **base64(tar.gz)**；头 `Authorization: Bearer <token>` |

**为什么上行是 base64**：qi-runtime 的 web FFI（`RcStr::from_bytes`）会把请求体里内嵌的
`0x00` 逐个替换成空格以维持 C 串约定 —— 裸二进制上行必坏且坏得安静（长度不变只坏字节，
只有 sha256 才露馅）。下行不受影响（sendfile 绕开 qi 字符串）。**客户端下载侧同坑**：
tar.gz 响应体必须落到字节切片/文件，不能过 qi 字符串。运行时哪天提供「请求体字节句柄」，
两侧各改一行即可回归裸字节。

发布时服务端**必须**：解包校验 qi.toml 的 名称/版本 与 URL 一致（不一致 400）、
拒绝重复版本（409，版本不可变）、算 sha256 入库。错误响应
`{"error":"人话原因"}`。`uploaded_at` 为 UTC ISO 8601（`2026-08-15T14:51:47Z`）。
详情端点额外返回 `latest`/`downloads`（网页用，纯增量）。

认证只在 PUT；下载与查询公开。

## 客户端子命令

```
qi 包 安装                 # 读 [依赖]（或 qi.lock）→ 下载解压到 ./qi_packages/ → 写/校验 lock
qi 包 添加 <名称> <版本>   # 写进 qi.toml [依赖] 并安装
qi 包 发布                 # 打包当前目录 PUT 上去；token 读 QI_REGISTRY_TOKEN
qi 包 搜索 <关键词>        # 过滤包列表
```

注册中心地址默认 `https://pkg.qilang.org`，环境变量 `QI_REGISTRY` 覆盖（测试指本地）。

## 部署形态

注册中心用 **qi-web 写**（吃自己的狗粮）：PG 存元数据 + token，包体存文件系统
`store/<名称>/<版本>.tar.gz`。跑在 dell VM qpkg（192.168.123.66 / Tailscale），
qc-jp Caddy 反代出 pkg.qilang.org。
