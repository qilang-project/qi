# 编译器 async/await 状态机里程碑

**目标：** 让 qi 编译器把 `异步 函数 X(): 未来<T>` 转成真状态机，使 `等待 F` 是真正的 yield 点（不阻塞 tokio worker）。

**当前状态（2026-05）：**
- 语法上 `函数 X(): 未来<T>` 可声明 + `等待 F` 可调用
- 编译时：函数体**同步执行到尾**，`返回 V` 通过 `qi_future_ready_*(V)` 包成 Future
- `等待 F` → `qi_future_await_*(F)` → `block_in_place + handle.block_on(F.notified.await)`
- **缺：** 函数体不是状态机，`等待` 阻塞当前 tokio worker（虽然 block_in_place 让 tokio 可以 swap worker）

**这是 multi-week 工作。** 本文档把它拆成可独立实施的步骤。

---

## 1. 设计选型

### 不用 LLVM `@llvm.coro.*` intrinsics

理由：
- LLVM coro 需要 `coro-early/coro-elide/coro-split/coro-cleanup` pass，qi 现在 emit 文本 IR 直接走 `clang -O2`，没启 coro pass
- 加 coro pass 链路要改 `qi/src/lib.rs::compile_ir_to_object` —— 风险高
- coro intrinsics 跟 `promise` / `coro.id` 配合复杂，调试 IR-level 状态机麻烦

### 选：手写状态机

每个 `异步函数 X(...): 未来<T>` 编译生成两个 LLVM 函数 + 一个堆 frame：
- **入口 `X(args): *mut Future`**：alloc frame，spawn 第一次 poll，立即返回未完成 Future
- **`X_poll(*mut Frame)`**：根据 `frame.state` 跳转到对应 basic block，执行直到下一个 yield 点
- **frame**：args + locals + state_id + awaited_future_ptr + return_future_ptr

`等待 F` 翻成：
1. 保存当前 state_id 到 frame
2. 把 `X_poll` 注册为 F 的 waker
3. 立即 return（返回到 caller，通常是 tokio task scheduler）

F 完成时调 waker → 重新调 `X_poll(frame)` → switch 到正确 state 继续执行。

## 2. 状态机布局

### 源码

```qi
异步 函数 计算(x: 整数, y: 整数): 未来<整数> {
    变量 a: 整数 = 等待 异步获取(x);
    变量 b: 整数 = 等待 异步加(a, y);
    返回 b * 2;
}
```

### 生成 frame struct

```rust
#[repr(C)]
struct Frame_计算 {
    state: i64,                   // 0=initial, 1=after first await, 2=after second await, -1=done
    args_x: i64,
    args_y: i64,
    local_a: i64,
    local_b: i64,
    awaited_future: *mut Future,  // 当前正在 await 的 Future（poll 时取它的值）
    return_future: *mut Future,   // 调用方持有的返回 Future
}
```

### 生成入口 `计算(x, y) -> *mut Future`

```llvm
define ptr @计算(i64 %x, i64 %y) {
entry:
  %frame = call ptr @qi_async_alloc_frame(i64 56)        ; sizeof(Frame_计算)
  %fut = call ptr @qi_future_pending()                    ; pending Future for caller
  ; 写 frame.state=0
  %state_p = getelementptr %Frame_计算, ptr %frame, i32 0, i32 0
  store i64 0, ptr %state_p
  %x_p = getelementptr %Frame_计算, ptr %frame, i32 0, i32 1
  store i64 %x, ptr %x_p
  %y_p = getelementptr %Frame_计算, ptr %frame, i32 0, i32 2
  store i64 %y, ptr %y_p
  %ret_p = getelementptr %Frame_计算, ptr %frame, i32 0, i32 6
  store ptr %fut, ptr %ret_p
  ; spawn 第一次 poll —— 不阻塞调用方
  call void @qi_async_spawn_poll(ptr @计算_poll, ptr %frame)
  ret ptr %fut                                            ; 调用方拿到 pending Future
}
```

### 生成 poll fn `计算_poll(frame)`

```llvm
define void @计算_poll(ptr %frame) {
entry:
  %state_p = getelementptr %Frame_计算, ptr %frame, i32 0, i32 0
  %state = load i64, ptr %state_p
  switch i64 %state, label %unreach [
    i64 0, label %s0
    i64 1, label %s1
    i64 2, label %s2
  ]

s0:                                                       ; initial
  %x = load i64, ptr getelementptr (... args_x ...)
  %fut1 = call ptr @异步获取(i64 %x)                      ; nested async call
  ; 保存 awaited_future
  store ptr %fut1, ptr getelementptr (... awaited_future ...)
  ; 检查 fut1 是否已就绪（fast path: skip waker register）
  %ready = call i1 @qi_future_is_ready(ptr %fut1)
  br i1 %ready, label %s0_resume, label %s0_suspend

s0_suspend:
  store i64 1, ptr %state_p                              ; transition to state 1
  call void @qi_future_register_waker(ptr %fut1, ptr @计算_poll, ptr %frame)
  ret void                                               ; 让 caller (tokio) 跑别的 task

s0_resume:                                                ; fut1 已就绪
s1:                                                       ; entry from waker
  %a = call i64 @qi_future_value_i64(ptr %fut1)
  store i64 %a, ptr getelementptr (... local_a ...)
  ; 第二次 await
  %y = load i64, ptr getelementptr (... args_y ...)
  %fut2 = call ptr @异步加(i64 %a, i64 %y)
  store ptr %fut2, ptr getelementptr (... awaited_future ...)
  %ready2 = call i1 @qi_future_is_ready(ptr %fut2)
  br i1 %ready2, label %s1_resume, label %s1_suspend

s1_suspend:
  store i64 2, ptr %state_p
  call void @qi_future_register_waker(ptr %fut2, ptr @计算_poll, ptr %frame)
  ret void

s1_resume:
s2:
  %b = call i64 @qi_future_value_i64(ptr %fut2)
  store i64 %b, ptr getelementptr (... local_b ...)
  ; 返回 b * 2
  %result = mul i64 %b, 2
  ; complete return_future
  %retf = load ptr, ptr getelementptr (... return_future ...)
  call void @qi_future_complete_i64(ptr %retf, i64 %result)
  ; free frame
  call void @qi_async_free_frame(ptr %frame)
  ret void

unreach:
  unreachable
}
```

## 3. 需要加的 runtime 助手

`qi/src/runtime/async_runtime/state_machine.rs`（新文件）：

```rust
/// Alloc a heap frame of given size, zero-init
#[no_mangle]
pub extern "C" fn qi_async_alloc_frame(size: i64) -> *mut u8

/// Free heap frame
#[no_mangle]
pub extern "C" fn qi_async_free_frame(frame: *mut u8)

/// Spawn first poll on tokio runtime — handler signature: fn(*mut frame)
#[no_mangle]
pub extern "C" fn qi_async_spawn_poll(
    poll_fn: extern "C" fn(*mut u8),
    frame: *mut u8,
)

/// Register waker on Future: when future completes, will call poll_fn(frame)
#[no_mangle]
pub extern "C" fn qi_future_register_waker(
    fut: *mut Future,
    poll_fn: extern "C" fn(*mut u8),
    frame: *mut u8,
)

/// Check Future ready (without waiting)
#[no_mangle]
pub extern "C" fn qi_future_is_ready(fut: *mut Future) -> i32

/// Read i64 value out of completed Future (UB if not ready)
#[no_mangle]
pub extern "C" fn qi_future_value_i64(fut: *mut Future) -> i64

/// Mark Future complete with i64 value
#[no_mangle]
pub extern "C" fn qi_future_complete_i64(fut: *mut Future, value: i64)
```

`Future` 类型已存在（`runtime/async_runtime/future.rs`），需要扩展：
- 加 `wakers: Mutex<Vec<(extern fn, *mut u8)>>` 字段，complete() 时调用全部
- `register_waker` 在 state==Pending 时 push waker，已 Completed 则立即调用
- `is_ready` = state == Completed

## 4. 需要加的 codegen 改造（按顺序）

### 步骤 1：parser/AST 加 `异步` 关键字

**文件：**
- `qi/src/lexer/keywords.rs` — 加 `"异步"` token
- `qi/src/parser/grammar.lalrpop` — `FunctionDecl ::= "异步" "函数" Name ...`
- `qi/src/parser/ast.rs:104` — `FunctionDeclaration` 加 `is_async: bool` 字段

**测试：** parse `异步 函数 X(): 未来<整数> { ... }` 不报语法错误。

### 步骤 2：semantic 检查

**文件：** `qi/src/semantic/`
- 异步函数返回必须是 `未来<T>`
- `等待 F` 只能出现在异步函数体内（或顶层 `入口()`）
- F 必须是 `未来<T>` 类型

### 步骤 3：codegen 异步函数 frame 生成

**文件：** `qi/src/codegen/builder.rs`

新增 `fn build_async_function(&mut self, func: &FunctionDeclaration)`，调用点是现有 `build_node` 处理 `函数声明` 时检查 `is_async`。

逻辑：
1. 收集函数体里所有 `等待 X` 节点 — 数量 N，state ids 是 0..=N
2. 收集所有局部变量声明 — frame fields
3. 计算 frame struct layout（args + locals + state + awaited_future + return_future）
4. 生成入口函数 IR（alloc frame + spawn）
5. 生成 poll 函数 IR（switch on state，每个 await 切两个 basic block: suspend / resume）
6. 替换正常 `函数声明` 路径

**关键判断点（已存在）：** 
- `builder.rs:2467` 已检测 `TypeNode::未来类型` —— 当前路径是 sync wrap with `qi_future_ready_*`。新逻辑：如果 `is_async` 走 state machine，否则走老路径。

### 步骤 4：codegen `等待 F` 翻成 suspend/resume 块

**文件：** `qi/src/codegen/builder.rs:1898` 区域（`等待表达式` 已有处理）

异步函数上下文里：
- 把 `等待 F` 翻成两个 basic block + 一个 state 数字
- 不再调 `qi_future_await_*`（那是 sync 阻塞路径）
- 改调 `qi_future_register_waker`

### 步骤 5：runtime helpers

按 §3 加 `qi/src/runtime/async_runtime/state_machine.rs`，注册到 `mod.rs`。

### 步骤 6：异步 stdlib 函数补齐

**目标：** 让用户写 `等待 文件::异步读取(路径)` / `等待 数据库::异步查询(...)`。

最少需要：
- `网络::异步HTTP请求` — Web client
- `文件::异步读取/异步写入` — file IO  
- `时间::异步睡眠未来` — 已存在 ✅
- `网络::异步TCP*` — 已存在 ✅

新增 stdlib 异步函数都返回 `*mut Future`，FFI 签名兼容现有 `qi_future_ready_*`。

## 5. 边界情况清单（必须覆盖才能 ship）

- [ ] `等待` 表达式作为右值赋给变量：`变量 a = 等待 F` — 需要把 Future 值拿出来后再赋值
- [ ] `等待` 在 `如果` 分支里：`如果 (cond) { 等待 F1 } 否则 { 等待 F2 }` — state id 分别管理
- [ ] `等待` 在 `当` 循环里：`当 (cond) { 等待 F }` — 循环每次都生成 suspend/resume，state id 复用？还是每次循环新 state？后者 = state id 数量动态，frame 不能定长 → 可能改用栈式 state stack
- [ ] 异步函数嵌套调用：`等待 异步函数A()` 里 A 也是 async — A 返回 Future，外层 await 它，正常工作
- [ ] 异常 / panic：异步函数体抛出 → frame 必须 free，return_future 必须 fail
- [ ] 异步函数的 `返回` 在嵌套块里：`如果 (...) { 返回 v }` — 多个 return 路径都要 complete + free frame
- [ ] 异步函数没有 `等待`：可以保留旧 sync wrap 路径（`qi_future_ready_*`），不强制走 state machine
- [ ] 异步函数有 await 但调用栈来自非 tokio 上下文：fallback `block_on` — 需要 spawn_poll 在非 tokio 时用全局 runtime

## 6. 风险评估

| 风险 | 缓解 |
|---|---|
| 状态机 codegen 跟现有 sync wrap 路径冲突 | 加 `is_async` flag 严格隔离；旧路径用于"未来类型 但无 await"函数 |
| 循环里 await 导致 frame size 不定 | 第一版限制：循环里禁止 await；下一版加栈式 state |
| 嵌套 async 调用栈深 | poll fn 重入安全；把 poll 放 `tokio::spawn` 解 stack |
| 跨 FFI 栈传播 panic | 异步入口 wrapper 用 `catch_unwind`，panic 时 fail frame |
| qi 现有 `未来<T>` 函数破坏 | 必须保持向后兼容：无 `异步` keyword 则走老路径 |

| 场景 | 收益 |
|---|---|
| qi-web bench (无真 IO 的 hot path) | **0** — 用不到 |
| qi-web 真实 handler（DB 查询 / HTTP 调用） | 大 — handler 可用 N=12 worker 跑无限并发 |
